Rules established by the issue #119 flaky-test sweep (2026-07-04), applying to all new UI tests. The helper *code* is readable in the target; what's recorded here is the non-obvious *why* and the invariants future tests must not break.

- **Tap-after-scroll needs a settle probe.** An inertial `swipeUp` leaves the list decelerating and the next tap is swallowed as a scroll-stop touch (issue #119 sighting 2). Use `revealTapAndSettle(_:scrollingIn:pushSentinel:timeout:)` / `LibraryScreen.openRow(labelContains(All):pushSentinel:timeout:)` (LibraryScreen.swift): reveal → tap → ~3s sentinel probe → one re-tap. It deliberately returns after the re-tap; the CALLER's `.postNavigation` first-wait supplies the full window — don't add a second long wait inside helpers. `LibraryScreen.openEnglishUS(timeout:)` is the no-scroll variant (row is above the fold in portrait; self-sufficient by design, keep it independent of `waitForRevealed`).
- **Tests that present remote system UI (share sheet) must clean up in-test AND register a terminate backstop.** issue #119's root flake: a live share sheet left up makes the next `launch()` kill the process mid-presentation (issue #62's failure line). Pattern in `test_exportBuiltIn_presentsShareSheet`: `dismissShareSheet` + `addTeardownBlock { @MainActor [app] in app.terminate(); _ = app.wait(for: .notRunning, timeout: 10) }` right after launch, and tearDown's screenshot guarded with `app.state != .notRunning`. Dismissal order (empirical, 2026-07-04 validation run): the iOS 26 sheet hosts its content out of process and exposes NO Close/Cancel button to the app's hierarchy — a container-scoped button probe fails every time — so after a 1s Close/Cancel probe (kept for other OS releases), the working gestures are a tap on the dimmed area above the sheet, then a drag of the sheet down past the bottom edge (both coordinate-based of necessity, like the AlternatesPopup mid-gesture exception). Do NOT assert on the underlying screen afterwards — the sheet dismisses back to the *detail* screen, and its list stayed in the hierarchy beneath the sheet the whole time (a `LibraryScreen.waitForContent` there was the first validation run's own bug: guaranteed 30s burn + failure on every green path). Share-sheet signatures are probed in BOTH the app's hierarchy and SpringBoard's (`XCUIApplication(bundleIdentifier: "com.apple.springboard")`) plus `app.popovers.firstMatch` (iPad); on timeout `waitForShareSheet` attaches `app.debugDescription` (`.keepAlways`) so OS renames are diagnosable from CI artifacts.
- **Never poll `app.keyboards` to detect typing readiness** — it burns the full timeout when the simulator's Connect Hardware Keyboard setting suppresses the software keyboard. Use the event-driven `waitForKeyboardFocus` gate (XCTNSPredicateExpectation on `hasKeyboardFocus == true`, ~5s, one re-tap on miss), duplicated by design in SymbolReferenceScreen.swift and KeyEditorScreen.swift (SymbolReferenceScreen stays self-contained per its header).
- **IPAKeyboardUITestsLaunchTests.tearDown now restores portrait and terminates the app** (confirmed-dead via `wait(for: .notRunning)`). The launch tests were the ONLY source of leftover-landscape; the functional suites' portrait one-liners in setUp are now belt-and-braces with nothing to race — keep both, and do NOT add per-suite window-geometry gates (redundant, and a latent full-timeout burn under a legitimately-landscape iPad configuration).
- **Negative-assertion polarity:** when something legitimately existed and is going away, assert `waitForNonExistence(timeout:)` (eventual state), not `XCTAssertFalse(waitForExistence(2))` (snapshot race). Keep `XCTAssertFalse(x.waitForExistence(short))` only for things that must NEVER appear (e.g. a wrongful navigation push) and run that negative probe FIRST so its window doubles as the settle time the wrong outcome would need.
- **Coexistence with PR #118** (`99-either-or-alert-probes`): it inserts a `waitForEither(_:_:scrollingSecondIn:timeout:)` free function immediately after `waitForRevealed`'s closing brace in LibraryScreen.swift and rewrites `duplicateBuiltInLayout` + `test_importValid_succeedsOrDegradesGracefully`. Until it merges, don't edit those regions; the sweep's `waitForRevealed` rewrite kept everything from its closing brace onward byte-identical to minimize the merge conflict.
